# 6APA 本体 Demo v2 设计说明

## 1. 界面结构

```
┌ 顶栏：搜索（工序 / 设备组 / 设备 / 位号 / 现象）· 「试算数据为模拟数据」· 恢复种子数据 ┐
├ 左：分类 + 导航树 ─────────┬ 右：显示区 ─────────────────────────────────────────┤
│ 空间层级 工业资产 工艺参数    │ 车间概览 / 工艺段概览 / 工序概览                          │
│ 物料与产品 质量 组织与人员    │ 工序图纸（P&ID 示意）                                     │
│ 能源 经营与成本              │ 装置 / 计算组态 / 工况与根因 / 文档提取                    │
│                             │ 设备 / 设备组：10 个页签                                  │
└─────────────────────────────┴──────────────────────────────────────────────────────┘
```

### 1.1 空间层级（车间导航）

| 层级 | 内容 | 交互 |
|---|---|---|
| 车间 | 105车间 | 第一屏只显示车间与工艺段，不出现设备、参数 |
| 工艺段 | 6A_提取、6A_脱色、6A_抽提、6A_水解、6A_结晶、6A_干燥 | 单击看概览；**双击**进入工艺段内的层级树（顶部「返回车间导航」退回） |
| 工序 | 一张 DCS 流程画面（P&ID），如 水解A-F | **单击**选中（概览）；**双击**或点「进入」打开图纸 |
| 工序下 4 个节点 | 装置、计算组态、工况与根因、文档提取 | 单击打开对应视图 |
| 装置下 | 设备组（文件夹）→ 设备；未入组设备直接挂在装置下（斜体） | 单击打开设备 / 设备组的 10 个页签 |

子工序写在图纸上（图纸顶部的胶囊条），不单独做一层导航。

见 `data/config/6APA_空间层级.xlsx`（`backend/tools/build_config.py` 生成，可人工修改后重启生效）：

| 6A_脱色 | 脱色 | S06 |
| 6A_抽提 | 抽提 / 薄膜 | S07 / S09 |
| 6A_水解 | 水解A-F / 水解G-K / 水解配置 / 萃取 | S11（按罐号拆）/ S10 / S12 |
| 6A_结晶 | 结晶_北排 / 结晶_南排 / 连续结晶 / 结晶氨水 | S13（按罐号拆）/ S14 / S15 |
| 6A_干燥 | 干燥 | S16 |

设备归属规则：按「工段编号」取点表设备；「设备匹配(正则)」非空的工序只认领名称匹配的设备，
其余归该工段的默认工序（设备匹配为空的那道）。

- 水解G-K 认领 `水解罐G–K`、`氨水计量罐G–L`、`L罐`（点表台号跳过 I：水解罐I/J/K 的氨水计量罐写作 J/K/L）；

- 设备组是文件夹：一个设备组的成员可分属两道工序（如 水解反应釜组 A–F / G–K），各工序下只列本工序认领的成员；
  设备组只在自己工段的工序下展开，其他工段的共用设备不跨工段挂进来。

未纳入导航树的工段：S08 钾盐支线、S17–S23（母液回收、溶媒回收、苯乙酸回收、废酸水、吸附、公用工程、尾气）、S99 备用点。

### 1.4 工序图纸

- **现场图纸**：`data/drawings/<工序编号>.json` + 图片。JSON 里登记图片尺寸和热区（原图像素坐标 x / y / w / h + 点表设备名），
  后端按名称把热区落到本体对象（先本工序、再同工艺段、再全厂），落不到的列在 `unresolved`；
  `confirmed: false` 的热区是按画面位置 / 文字推断的，界面上画紫色虚线框；
- 目前只有 **水解A-F**（`OP-09`，用户提供的 DCS 流程画面截图，19 个热区）；其余工序没有原图时显示本体示意图，
  有原图的工序也可切换到示意图；
- 热区单击打开对应设备；属于其他工序的设备（如画面上的硼酸缓冲罐，点表归属 水解配置）打开时带它自己的工序；
- 选中设备时高亮该设备的热区，选中设备组时高亮组内全部成员；
- 新增一道工序的原图：把图片放进 `data/drawings/`，照 `OP-09.json` 写一个同名 JSON，重启后端即可。

画面与点表的核对项（水解A-F）：

| 画面 | 点表 | 处理 |
|---|---|---|
| 底部中间罐「水解?缓冲罐 A」，RB液来至薄膜、RB高液位回流提示，液位位号显示 LT_1301B | RB储罐A 的液位是 LT_1301A，LT_1301B 属 RB储罐B | 热区挂 RB储罐A，待核对 |

| 画面底部导航栏的画面清单 | 与 `6APA_空间层级.xlsx` 的 17 道工序一致 | 印证了工序口径 |

## 2. 设备 / 设备组的 9 个页签

| 页签 | 内容 | 数据来源 |
|---|---|---|
| 图纸位置与外观 | 所在工序图纸（本对象高亮）、固有属性、本工序内的成员 | 层级配置 + 点表 + 设备主数据 |
| 参数 | 一张表按类别筛选：基本信息、设计参数（材质 / 容积 / 高度…）、工艺属性、测量、状态、控制；DCS 位号直接列在行里（设备组把各成员的测量 / 状态 / 控制按名称合并） | 点表、工业关系表、`data/config/6APA_设备设计参数.xlsx` |
| 参数约束 | 工艺限值（LL / L / 正常 / H / HH）及限值版本；「工况」列与版本「适用条件」关联到工况现象，点击跳到现象定义 | 工艺限值表、限值版本 |
| 拓扑关系 | 物理拓扑、结构关系、空间层级、实例间连接 | 工业关系表、实例连接表 |
| 现象定义 | 本对象及所属设备组上的现象 + 判定规则，可新增 / 编辑 / 试算 | **v2 新增** |
| 根因影响关系 | 涉及本对象现象的导致关系，列表 + 图谱 | **v2 新增** |
| 工艺影响关系 | 工艺属性之间的正向 / 负向影响、质量关系 | 工业关系表 |
| 计算/指标 | 挂在本对象（或所属设备组）的计算组态，可试算；尚无测点的派生属性；已登记能力 | **v2 新增** + 能力登记表 |
| 处置规程 | 相关报警处置卡（触发、原因、步骤、禁止操作） | 处置规程表 |

设计参数：`backend/tools/build_design_params.py` 生成 `data/config/6APA_设备设计参数.xlsx`。「参数模板」按设备类型
（固定化酶反应罐、搅拌罐、储罐 / 计量罐、泵、离心机、换热器、塔器）列出应有的参数；设备先按名称、再按设备组类型命中模板。
「参数值」表按 对象名称 + 参数名 填写（设备组上的值对组内每台生效，设备上的值优先）。点表里没有铭牌数据，初始全部为「待补充」。

「继承」列：参数、参数约束、拓扑关系、现象定义、根因影响关系、工艺影响关系、计算/指标 每条前有一个只读勾选框，
勾选 = 继承自类对象（设备组，或设计参数的设备类型模板），由本体推导：属性 / 限值随设备组的工艺属性继承，
拓扑关系中「所属组」层继承，现象 / 计算组态挂在设备组上即继承，导致关系两端都不是本对象自有现象即继承。

## 3. 现象与根因影响关系

### 3.1 现象

现象 = 当前情况的描述 + 判定规则，例如「水解罐pH偏高」「反应期搅拌停止」「水解液缓冲罐高位」「泵/电机非指令停机」。

```json
{
  "id": "PH-S11-03", "name": "水解罐pH偏高",
  "anchor": {"kind": "group", "id": "egrp-…", "name": "水解反应釜组(水解罐A–K)"},
  "category": "工艺", "severity": "警告", "status": "草案·待工艺确认",
  "rule": {"type": "group", "op": "OR", "children": [
    {"type": "condition", "subject": {"kind": "parameter", "name": "反应体系pH"}, "aggregate": "mean",
     "operator": ">", "threshold": {"kind": "limit", "limitId": "PL002", "field": "normalHigh"}, "durationSec": 60},
    {"type": "condition", "subject": {"kind": "parameter", "name": "反应体系pH"},
     "operator": ">", "threshold": {"kind": "limit", "limitId": "PL002", "field": "high"}, "durationSec": 0}
  ]}
}
```

- **挂载对象**：设备组或设备。设备组上的现象对组内每台设备分别判定，在设备的「现象定义」页签里标「继承自设备组」；
- **判定规则**：条件树，「与（AND）/ 或（OR）」可任意嵌套，从多个维度组合判定；
  - 条件主体：`parameter`（本对象的工艺属性 / 测量 / 状态 / 控制，自动落到本台的测点）、`tag`（直接指定位号）、
    `calc`（计算组态的输出）；
  - 一个属性落到多个测点时（如每罐两支 pH 计）：`any` 任一测点 / `all` 全部测点 / `mean` 测点均值；
  - 运算：`> >= < <= = !=`，以及 `change`（由 from 变为 to，如运行反馈由 1 变 0）；
  - 阈值：数值，或引用工艺限值（`PL002` 的 正常上限 / 高限 …），限值变了规则自动跟着变；
  - 持续时长 `durationSec`：原始条件连续成立满这么久才算成立；
- **既可以是原因也可以是结果**：角色不写在现象上，由根因影响关系决定（列表里显示「因 n / 果 n」）；
- 判定规则可以暂不定义（如「固定化酶活力下降」——酶活无法在线检测），这样的现象只能作为图谱节点，不能试算。

### 3.1.1 工况现象（被参数约束引用）

类别为「工况」的现象描述运行状态，带 `conditionKey`，被参数约束引用：

- 限值的「适用工况」：每个（工段，工况）一条，如 `工况·水解反应期`（mode:S11:水解反应期）。S11 的进料过程 / 水解反应期 / 出料过程
  按 6APA_工序与阶段.xlsx 的 DCS 识别条件写判定规则，其余工况先只登记、判定规则待定义；
- 限值版本的「适用条件」：换酶后批次区间，如 `换酶后第 801～∞ 批`（batch:S11:801-）、`换酶后第 1～800 批`。判定规则的条件主体是
  运行上下文 `上下文.换酶后批次数`（来自 EBR），本 Demo 未接入，试算显示「无法判定」。只有一个 [a, ∞) 版本时，基础版本 V0 关联到 1～a-1 批。

### 3.2 根因影响关系

一条记录 = 「原因现象 **导致** 结果现象」，附机理说明、依据、置信度（高 / 中 / 低）、状态。

- 列表：可按结果现象分组（「由 n 个现象导致」）或平铺；
- 关系图谱：按导致关系分层，左为根因、右为结果；虚线框 = 判定规则待定义，虚线边 = 低置信度；悬停高亮相邻关系；
- 选中一个结果现象（列表点结果名、图谱点节点）→ 弹窗：它的判定规则、**由什么导致**（逐层往上追溯，图谱 + 按层列表）、
  会导致什么；弹窗里可直接「补一条原因」、试算、沿链路点下去（「← 上一个」返回）。
- 校验：原因、结果必须是已有现象；不能自己导致自己；同一对 原因 → 结果 不能重复登记。删除现象时一并删除相关导致关系。

### 3.3 试算

判定规则与计算组态都可在**模拟数据**上试算（`backend/v2/simulator.py`），结果标「模拟数据」：

- 值是（种子, 位号, 时间）的纯函数，同一时间窗两次试算结果一致；
- 模拟量以该位号工艺限值的正常区间为中心波动，按 3 小时时间片随机出现偏离片段，使现象有机会成立；
  液位为锯齿（下降 → 补液）；开关量按设备共享状态（偶发跳闸、停机、就地、阀门指令与反馈不一致）；
- 限值引用按基础版本（V0）取值，暂未按时刻生效的限值版本求值。

## 4. 计算组态

一条计算组态 = 挂载对象 + 方法 + 输入绑定 + 输出单位，设备组上的组态对组内每台分别计算。

| 方法 | 说明 | 种子示例 |
|---|---|---|
| `formula` | 表达式（白名单函数 `abs mean max min sum sqrt where`）；输入带 `index` 取该属性第 n 个测点 | pH双支偏差 `abs(a - b)`；水解罐平均温度 `mean(t)` |
| `level_consumption` | 液位差消耗量：只累计下降（上升视为补液），死区过滤，按滑动时间窗折算速率；算法复制自 Agent Demo | 加氨速率（液位差法） |
| `rate` | 滑动时间窗内的平均变化速率 | 缓冲罐液位上升速率 |

计算组态的输出可以在判定规则里当条件主体（如「pH双支偏差 > 0.2 持续 5 分钟」→ 现象「pH双支偏差大」）。

## 5. 文档提取

- 规程类文档：`docs/source-docs/` 下登记的文档（当前只有 SOP-S11-ALARM-001，**模拟规程**），列出从中提取的处置卡、
  据此整理的现象，可查看原文；
- 数据源文档：本工序从点表、工业关系、工艺限值、处置规程中提取的条数。

## 6. 种子数据

`backend/tools/build_seed.py` 生成 `data/seed/*.json`，全部为「草案·待工艺确认」：

- **6A_水解（S11）标杆**：按规则表 R-S11-* / R-G-* 与处置卡 ARP-S11-* 手工整理 23 个现象、24 条导致关系、4 个计算组态；
- **其余工段**：由处置卡自动生成。报警现象（有限值的给出判定规则）+ 卡片「可能原因」→ 原因现象（判定规则待定义）+ 导致关系；
- 没有限值、只能给占位阈值的，在备注里写明「占位阈值，待现场提供」。

运行时编辑保存在 `data/store/`（首次启动从 seed 复制，不进 git），顶栏「恢复种子数据」可还原。
