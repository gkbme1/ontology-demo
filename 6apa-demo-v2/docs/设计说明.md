# 深冷装置本体 Demo v2 设计说明

场景：北I-2 深冷装置（油气加工三大队）。界面沿用 6APA 本体 Demo v2，数据换成深冷装置；6APA 版数据存档在 `data/archive/6apa/`。
**口径：DCS 流程画面与点表为准**；操作规程（WJ/TRQ/03-09-04）是旧版，只在画面 / 点表没有的内容上作参考，相关条目都是「草案·待工艺确认」。

## 1. 界面结构

```
┌ 顶栏：搜索（画面 / 设备组 / 设备 / 位号 / 现象）· 「试算数据为模拟数据」· 恢复种子数据 ┐
├ 左：分类 + 导航树 ─────────┬ 右：显示区 ─────────────────────────────────────────┤
│ 空间层级 工业资产 工艺参数    │ 装置概览 / 单元概览 / 画面概览                          │
│ 物料与产品 质量 组织与人员    │ 画面图纸（P&ID 示意）                                     │
│ 能源 经营与成本              │ 装置 / 计算组态 / 工况与根因 / 文档提取                    │
│                             │ 设备 / 设备组：10 个页签                                  │
└─────────────────────────────┴──────────────────────────────────────────────────────┘
```

## 2. 设备 / 设备组的 9 个页签

| 页签 | 内容 | 数据来源 |
|---|---|---|
| 图纸位置与外观 | 所在画面图纸（本对象高亮）、固有属性、本画面内的成员 | 层级配置 + 点表 + 设备主数据 |
| 参数 | 一张表按类别筛选：基本信息、设计参数（材质 / 容积 / 高度…）、工艺属性、测量、状态、控制；DCS 位号直接列在行里（设备组把各成员的测量 / 状态 / 控制按名称合并） | 点表、工业关系表、`data/config/6APA_设备设计参数.xlsx` |
| 参数约束 | 工艺限值（LL / L / 正常 / H / HH）及限值版本；「工况」列与版本「适用条件」关联到工况现象，点击跳到现象定义 | 工艺限值表、限值版本 |
| 拓扑关系 | 物理拓扑、结构关系、空间层级、实例间连接 | 工业关系表、实例连接表 |
| 现象/工况定义 | 本对象及所属设备组上的现象与工况 + 判定规则，可新增 / 编辑 / 试算 | **v2 新增** |
| 根因影响关系 | 涉及本对象现象的导致关系，列表 + 图谱 | **v2 新增** |
| 工艺影响关系 | 工艺属性之间的正向 / 负向影响、质量关系 | 工业关系表 |
| 计算组态 | 挂在本对象（或所属设备组）的计算组态，可试算；尚无测点的派生属性；已登记能力 | **v2 新增** + 能力登记表 |
| 处置规程 | 相关报警处置卡（触发、原因、步骤、禁止操作） | 处置规程表 |

设计参数：`backend/tools/build_design_params.py` 生成 `data/config/6APA_设备设计参数.xlsx`。「参数模板」按设备类型
（固定化酶反应罐、搅拌罐、储罐 / 计量罐、泵、离心机、换热器、塔器）列出应有的参数；设备先按名称、再按设备组类型命中模板。
「参数值」表按 对象名称 + 参数名 填写（设备组上的值对组内每台生效，设备上的值优先）。点表里没有铭牌数据，初始全部为「待补充」。

「继承」列：参数、参数约束、拓扑关系、现象定义、根因影响关系、工艺影响关系、计算/指标 每条前有一个只读勾选框，
勾选 = 继承自类对象（设备组，或设计参数的设备类型模板），由本体推导：属性 / 限值随设备组的工艺属性继承，
拓扑关系中「所属组」层继承，现象 / 计算组态挂在设备组上即继承，导致关系两端都不是本对象自有现象即继承。

设计参数：`data/config/设备设计参数.xlsx`，模板按设备类；「设备位号」取画面编号，「规格 / 型号」取规程（旧版）的说明，其余待补充。

## 3. 现象与根因影响关系

### 3.1 现象

现象 = 当前情况的描述 + 判定规则，例如「脱甲烷塔顶温度过低（CO2冻塔先兆）」「膨胀机振动高」「冷冻系统冻堵」。

```json
{
  "id": "PH-02", "name": "一级贫富气换热器差压高",
  "anchor": {"kind": "equipment", "id": "equip-…", "name": "一级贫富气换热器"},
  "category": "工艺", "severity": "警告", "status": "草案·待工艺确认",
  "rule": {"type": "group", "op": "OR", "children": [
    {"type": "condition", "subject": {"kind": "parameter", "name": "原料气压差"}, "aggregate": "any",
     "operator": ">", "threshold": {"kind": "value", "value": 30}, "durationSec": 300},
    {"type": "condition", "subject": {"kind": "parameter", "name": "原料气压差"}, "aggregate": "any",
     "operator": ">", "threshold": {"kind": "limit", "limitId": "PL-104PDT101", "field": "high"}, "durationSec": 0}
  ]},
  "note": "30 kPa 为规程表 4-4 甲醇加注操作点"
}
```

- **挂载对象**：设备组或设备。设备组上的现象对组内每台设备分别判定，在设备的「现象定义」页签里标「继承自设备组」；
- **判定规则**：条件树，「与（AND）/ 或（OR）」可任意嵌套，从多个维度组合判定；
  - 条件主体：`parameter`（本对象的工艺属性 / 测量 / 状态 / 控制，自动落到本台的测点）、`tag`（直接指定位号）、
    `calc`（计算组态的输出）；
  - 一个属性落到多个测点时（如压缩机润滑油总管 4 支压力变送器）：`any` 任一测点 / `all` 全部测点 / `mean` 测点均值；
  - 运算：`> >= < <= = !=`，以及 `change`（由 from 变为 to，如运行反馈由 1 变 0）；
  - 阈值：数值，或引用工艺限值（`PL-104PT111` 的 正常上限 / 高限 …），限值变了规则自动跟着变；
  - 持续时长 `durationSec`：原始条件连续成立满这么久才算成立；
- **既可以是原因也可以是结果**：角色不写在现象上，由根因影响关系决定（列表里显示「因 n / 果 n」）；
- 判定规则可以暂不定义（如「固定化酶活力下降」——酶活无法在线检测），这样的现象只能作为图谱节点，不能试算。

深冷种子数据里的规则都挂在设备 / 设备组上；运行上下文（分子筛程序阶段、运行工况、班次）本 Demo 未接入，用作条件主体时试算显示「无法判定」。

### 3.2 根因影响关系

一条记录 = 「原因现象 **导致** 结果现象」，附机理说明、依据、置信度（高 / 中 / 低）、状态。

- 列表：可按结果现象分组（「由 n 个现象导致」）或平铺；
- 关系图谱：按导致关系分层，左为根因、右为结果；虚线框 = 判定规则待定义，虚线边 = 低置信度；悬停高亮相邻关系；
- 选中一个结果现象（列表点结果名、图谱点节点）→ 弹窗：它的判定规则、**由什么导致**（逐层往上追溯，图谱 + 按层列表）、
  会导致什么；弹窗里可直接「补一条原因」、试算、沿链路点下去（「← 上一个」返回）。
- 校验：原因、结果必须是已有现象；不能自己导致自己；同一对 原因 → 结果 不能重复登记。删除现象时一并删除相关导致关系。

### 3.3 试算

判定规则与计算组态都可在**模拟数据**上试算（`backend/v2/simulator.py`），结果标「模拟数据」：

- 值是（种子, 位号, 时间）的纯函数，同一时间窗两次试算结果一致；
- 模拟量以该位号工艺限值的正常区间为中心波动，按 3 小时时间片随机出现偏离片段，使现象有机会成立；
  液位为锯齿（下降 → 补液）；开关量按设备共享状态（偶发跳闸、停机、就地、阀门指令与反馈不一致）；
- 限值引用按基础版本（V0）取值，暂未按时刻生效的限值版本求值。

深冷补充：没有限值正常区间的位号按点表量程（35%～60%）取值，个别按 `data/config/模拟基准.json`（只给模拟器用，不是工艺限值）；
报警 / 故障 / 停机类开关量平时为 0，跳闸片段为 1。

## 4. 计算组态与算法库

计算组态、工况与根因、文档提取属于全局（跨设备 / 跨工艺），不挂在某道画面下；画面页头部的「计算组态 ↗ / 工况与根因 ↗ /
文档提取 ↗」打开全局视图并筛选到本画面。设备页签里的「计算组态」「现象/工况定义」「根因影响关系」只显示与本对象相关的条目。

**算法库**（`data/config/6APA_算法库.json`，`backend/v2/algorithms.py`）只登记算法的调用契约：调用方式（协议 / 方法 / 地址）、
输入参数（名称、类型、单位、必填、默认值）、输出。算法本身由算法服务提供；本 Demo 用内置实现代替，部署时换成调用算法服务，
计算组态不用改。

**计算组态**不写算法本身，只「引用算法 + 绑定参数」：

```json
{"id": "CALC-03", "name": "两台膨胀机转速差", "anchor": {"kind": "segment", "id": "SEG-04", "name": "冷冻分离单元"},
 "algorithmId": "ALG-RANGE",
 "bindings": {"series": {"kind": "groupParameter", "groupId": "egrp-…", "name": "膨胀机转速"}}}
```

绑定类型：`parameter` 本对象参数（设备组上的组态对组内每台分别计算，`index` 取第 n 个测点）、`groupParameter` 设备组全部成员的参数
（跨设备统计）、`tag` 位号、`calc` 另一条计算组态、`const` 常量（算法配置参数，如时间窗）。作用范围可以是设备、设备组或单元。

## 6. 数据与种子

数据链：DCS 点表 + 操作规程 + 画面截图 → `cryo_knowledge.py`（人工梳理）+ `build_cryo_ontology.py`（自动归属）→
`data/cryo/北I-2深冷_本体.xlsx` → `build_cryo_sources.py` → `data/source/*.xlsx`、`data/config/*.xlsx` → `build_cryo_seed.py` → `data/seed/*.json`。

- **工艺限值**：一律挂点表位号（适用对象类型「DCS点」）。同一位号的附录二运行区间与附录四报警 / 联锁值合并成一条 `PL-<位号>`（正常运行），
  开车确认 `-S`、自动控制设定 `-C`、热吹 / 冷吹 `-R` 另列；全部「规程（旧版）参考」「草案·待工艺确认」；
- **现象**：42 个（40 个有判定规则），阈值优先引用工艺限值，没有限值的写数值并在备注写来源（规程章节或「占位阈值，待现场提供」）；
- **根因影响关系**：31 条，规程原文为主，机理推断的标「按机理推断」、置信度中 / 低；
- **计算组态**：8 个（塔顶温度变化速率、重烃储罐液位上升速率、两台膨胀机转速差、压缩机电机定子平均温度、换热器原料气差压上升速率、膨胀机振动差、重烃收集罐烃室液位上升速率、变频重烃泵输出与反馈偏差）；
- **处置卡**：9 张，ARP-01～08 步骤取自规程正文；
- **现场异常排查表**（用户提供，目前 1 条）：「重烃收集罐烃室液位持续上涨」建成现象 PH-36，7 项排查方式中的 6 项各建一个原因现象（PH-37～42，
