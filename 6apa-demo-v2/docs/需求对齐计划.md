# 需求对齐计划（对照《工业本体模型 系统需求规格 V0.5》）

原则：需求中有、Demo 中没有的直接补；两边都有但不一致的，按更合适的一方改（多数按需求，Demo 更贴合现场的保留并在此说明）。
开发态修改触发工程态更新（类库更新同步）不做。每批做完给用户看过再做下一批。

保留 Demo 做法（建议反向修订需求文档）：
- 现象类别保留 8 类（工况 / 工艺 / 设备 / 仪表 / 操作 / 物料 / 公用工程 / 环境），需求只写了 3 类；
- 判定规则保留 `change`（由 A 变 B）运算和「计算组态输出」作条件主体；
- 参数约束保留「限值版本」（按换酶后批次等条件生效）——制药场景需要，需求里没有；
- 子工序写在图纸 / 示意图顶部，不作为树节点（需求 SW-002 允许子工序作为层级，105 车间暂无子工序级对象）。

## 第 2 批（已完成）：对象详情的工程态组态

| 需求条目 | 内容 | 处理 |
|---|---|---|
| SW-004 / 005 / 028 | 属性与参数分开、参数类别、位号绑定状态 | 参数页签分「属性」（基本信息、设计参数）与「参数」（测量值 / 设定值 / 阀位 / 控制指令 / 状态 / 计算值，按位号的变量类别归类）；每个参数显示绑定状态 已绑定 / 待确认 / 未绑定 / 失效，可筛选 |
| SW-026 / 045 / 046 | 继承覆盖、禁用、恢复继承 | 设备上可覆盖设备组现象的阈值 / 持续时长、覆盖设备组限值（显示模板值对比），或禁用；来源列显示「已覆盖 / 已禁用」；模拟试算按本台覆盖判定 |
| SW-046 | 手工输入试算 | 试算弹窗增加「手工输入」：填各条件主体的当前值，按瞬时值判定（单文件版可用） |
| SW-044 / 049 | 拓扑 / 工艺影响关系增删 | 页签内「+ 新增关系」：物理拓扑 / 工艺流向 / 供应 / 工艺影响，端点按关系类型校验，对端支持拼音搜索；人工关系可删除，同步到全局图谱和一致性校验 |
| SW-041 第 4、5 条 / SW-062 | 基础信息、被引用、变更记录、浏览后退 | 对象页头「基础信息 · 变更记录」；现象 / 导致关系 / 计算组态 / 覆盖 / 人工关系的增删改都记变更（字段前后值，规则显示为自然语言）；顶栏「← 后退」 |

说明：
- 「控制指令」（DO 启停 / 开关阀 / 电机块）是需求参数类别之外新增的一类，需求只列了 测量值 / 设定值 / 阀位 / 状态 / 计算值 / 设计值；设计值归到「属性 · 设计参数」；
- 覆盖、人工关系、变更记录保存在 `data/store/`（`overrides.json`、`user_relations.json`、`audit.json`）；「恢复种子数据」清除覆盖与人工关系，变更记录保留并追加一条；
- 单文件版只读展示这些内容（不能覆盖 / 新增关系，不记变更）；手工输入试算可用。

| SW-051 第 4 条 | 现象详情中查看关联规程 | 现象弹窗显示「关联规程」，点开看处置规程 |
| SW-050 / 074 | 计算组态执行设置、编辑、校验、运行状态 | 执行方式 周期 / 事件触发 / 按需、周期、超时、失败处理（重试 / 跳过、连续失败停用）、输出测点与是否写回 XBase；页签与全局视图可新建 / 编辑 / 删除；保存校验必填绑定、类型匹配（时序 ↔ 常量）、参数 / 位号 / 计算组态引用存在、不引用自己；运行状态显示最近一次试算 |

说明：
- 「是否需人工确认」按原文的 auto 标记预置：确认 / 对比类步骤为「系统辅助」，其余为「是」；授权要求预置「待企业 SOP 确认」，不编造；
- 本 Demo 没有调度器，计算组态的执行设置只登记，运行记录来自试算（内存，重启清空）；
- 处置规程编辑保存在 `data/store/procedure_edits.json`；单文件版只读。
