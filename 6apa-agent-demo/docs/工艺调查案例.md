# 内置工艺调查案例

Demo 里内置了 23 条示例问题，分 5 组。打开对话页就能看到，点一下把问题填进输入框。

**这些案例不是写死的业务流程。** 点击只做一件事：把问题文本填进输入框。
Agent 收到的和你手敲进去完全一样，工具选哪个、调几次、先查什么后查什么，
全部由模型自己规划。本文档里的「参考工具链」只给演示和验收时对照用，
不下发给模型，也不参与规划——本项目禁止针对具体问题写死流程，这条线没有破。

案例数据在 `backend/data/examples.json`，改完调 `POST /api/examples/reload` 即可生效，不必重启。
前端从 `GET /api/examples` 拉取；接口不可用时退回组件内置的几条兜底问题。

## 一、工艺调查（异常溯源）· 6 条

这是这次新增的重点。调查型问题的通用做法已经写进 `backend/prompts/system_prompt.txt`
的「工艺调查类问题的通用做法」一节——同样是通用方法，不绑定任何具体设备或参数：

> 落实对象与时间 → 先用限值和历史值确认异常成不成立 → 沿本体因果关系找候选原因
> → 把原因落到测点 → 取同一时间窗的历史值比时间/方向/幅度 → 分三层给结论并列出数据缺口

### INV-01　昨天水解罐温度异常，帮我调查一下原因

最典型的一条，也是最能看出本体价值的一条。

**参考工具链**

```
query_equipment_list / query_relation_entities   名称 → ID
query_object_limits                              PL001：正常 33~35 ℃，高限 35.5，高高限 37
query_history_values                             昨天整天的 TI_1301A~L 曲线，确认异常时段与最值
query_relations(entityId=robj-…)                 拿全该对象的 7 条关系（用 query_object_relations
                                                 会连匹配实例和测量锚点一起带回来，返回体大易被裁）
query_causal_relations                           看有没有更上游的两跳影响
query_measurement_anchors                        这些影响因素有没有现场测点
query_history_values                             逐个取有测点的因素做同期对比
```

**本体里实际能查到什么**

影响釜内反应温度的因素有三个，全部带工艺机理说明：

| 影响因素 | 关系 | 工艺机理 | 现场测点 |
| --- | --- | --- | --- |
| RB进料温度 | 正向影响 | 底物来料温度高直接拉高初始釜温，破坏恒温控制 | **无** |
| 硼酸溶液温度 | 正向影响 | 缓冲液温度异常波动打破反应热平衡 | **无** |
| 夹套伴热蒸汽流量 | 正向影响 | 伴热进汽量增大导致反应釜温上升 | **无** |

再往上一跳：`热水罐出水温度（TI_1304、TI_1310，2 个测点） --正向影响--> RB进料温度 --正向影响--> 釜内反应温度`。

**合格的回答长什么样**

1. 先说异常成不成立：昨天 TI_1301A 最高 37.0 ℃，PL001 高高限 37 ℃，超了；限值状态是「待现场确认」。
2. 再说本体记了哪三个原因，各自的工艺机理与来源行号。
3. **必须明说**：这三个因素当前都没有现场测点，无法用数据验证——这是真实的数据缺口，不是查询失败。
4. 可以补一句：上游的热水罐出水温度有测点，可以取昨天的曲线作间接旁证。
5. 声明数据来源为模拟。

**不合格的回答**：跳过第 3 点，拿三个没有测点的因素当成「已验证的原因」；
或者自己编一个 35 ℃ 的阈值而不引用 PL001。

### INV-05　反应体系 pH 昨天波动比较大，是不是氨水加料引起的？

本体里少数**两端都有测点**的因果路径之一，可以把「取历史值验证」的闭环完整走一遍。

```
氨水加料流量（FT_1315，1 个点，m3/h） --正向影响--> 反应体系pH（22 支 pH 计）
```

昨天 08:00–16:00 的实际数据：FT_1315 在 7.4~18.3 m3/h 之间，AT_1301A1 在 7.83~8.01 pH 之间。
Agent 应该比较两条曲线的**先后、方向、幅度**，给出「与本体记载的正向影响一致」或
「未发现支持证据」，并显式标注这是分析结论而非本体数据。同时用 PL002 判断 pH 有没有越界。

### INV-06　水解进料换热温度偏高，可能是什么引起的？用数据验证一下

另一条两端可测的路径，关系方向是**负向影响**，专门用来检验 Agent 会不会看方向：

```
换热器冷盐水流量（HV_1016A_FB、HV_1016B_FB，%） --负向影响--> 水解进料换热温度（TI_1006A~C，°C）
```

「冷盐水流量下降 → 换热温度上升」才算对得上；方向反了必须说未发现支持证据，不能硬凑。
该温度有 PL003 限值可用。

## 自测

```bash
ONTOLOGY_BASE_URL=http://localhost:8700 python3 -m tests.test_examples
```

验两件事：示例文件结构合法、参考工具链里提到的工具名都真实存在；
以及工艺调查案例在本体里确实查得通——把关键几步打到真实本体上，

## 怎么增删案例

编辑 `backend/data/examples.json`，一条案例的字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 组内唯一，如 `INV-07` |
| `question` | 是 | 点击后填进输入框的问题文本，就是用户会问的原话 |
| `intent` | 否 | 这条想演示什么，鼠标悬停在按钮上时显示 |
| `referenceToolChain` | 否 | 仅供演示与验收对照，**不下发给模型** |
| `expectation` | 否 | 合格回答应该包含什么，用于人工验收 |

改完执行 `curl -X POST http://localhost:8800/api/examples/reload`，刷新页面即可看到。
