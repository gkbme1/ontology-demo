# 模拟 DCS 数据服务 · 接口说明

> ⚠️ **本服务返回的是模拟数据**，按每个测点的量纲与工艺位置"制造"出合理的数值，**不是现场真实读数**。
> 接入真实实时库 / 时序库时，把调用方指向真实地址即可，本服务整体丢弃，无需改调用方代码。

- 独立进程，默认端口 **8900**：`python3 -m mock_dcs.main` 或 `./run_mock_dcs.sh`
- 点表来自本体服务（`/api/ontology/tags`，10,680 个点）；本体服务不可达时服务照常可用，改为按位号名推断
- 业务错误一律 **HTTP 200 + 非零 code**，与实时库接口的 `code / message / data` 包装保持一致
- **本体服务已接入本服务**：本体对外提供 `/api/ontology/{对象ID}/realtime`、`/api/ontology/{对象ID}/history` 等 5 个接口，
  按设备 / 参数 / 关系对象查值并附带本体语义，本服务作为本体背后的"实时库 / 历史库"。
  业务方建议调本体接口，而不是直接调本服务（详见本体服务 README「实时值 / 历史值」）

## 一、nodeId 约定

```
{控制站号}:{位号}.{属性}
例：10:PT_1003.PV    13:AT_1301D1.PV    10:P_PZ_DO.PV
```

本体点表里（控制站号, 位号）唯一，所以每个 nodeId 都能对上一个真实测点。
点表里查不到的 nodeId（如接口示例里的 `100:AI001.PV`）默认按位号名推断生成；
设置 `MOCK_DCS_STRICT_NODES=true` 后改为返回 `q=0, v=null`。

不知道 nodeId 怎么写时：`GET /api/mock/nodes?keyword=排渣泵`

## 二、实时值

`POST /api/hsm-db-rtserver/v1/rtdata/node/read`

请求：

```json
{ "nodeIds": ["10:PT_1003.PV", "10:P_PZ_DO.PV"] }
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    { "nodeId": "10:PT_1003.PV", "st": 1790090507518, "t": 1790090507000, "q": 1, "v": 0.369 },
    { "nodeId": "10:P_PZ_DO.PV", "st": 1790090507518, "t": 1790083227000, "q": 1, "v": 1 }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `st` | 服务端时间（毫秒） |
| `t` | 值的时间戳：模拟量为最近一次扫描（1 s 对齐）；**开关量为最近一次变位时刻** |
| `q` | 质量：1 好；0 坏（备用未接线的模拟量、严格模式下不存在的点） |
| `v` | 值：模拟量为浮点（按量纲保留小数位）；开关量为整数 0 / 1 |

按请求顺序返回，单次最多 500 个点（`MOCK_DCS_MAX_NODES`）。

## 三、历史值（暂定格式，待对齐真实时序库）

`POST /api/timing-svc/v1/history/findAll`

请求：

```json
{
  "nodeIds": ["10:PT_1003.PV", "10:P_PZ_DO.PV"],
  "startTime": "2026-09-22 08:00:00",
  "endTime": 1790090507000,
  "interval": 60000,
  "sampleMode": "interpolated",
  "limit": 10000
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `nodeIds` | 是 | 同实时值 |
| `startTime` | 是 | 毫秒时间戳 / 秒时间戳 / `yyyy-MM-dd HH:mm:ss` / ISO 8601；字符串按东八区解析 |
| `endTime` | 否 | 同上，默认当前时刻；**晚于当前时刻时截到当前时刻**（历史只存在于过去） |
| `interval` | 否 | 采样间隔（毫秒，≥1000）。不填时自动选，使每点约 360 个样本 |
| `sampleMode` | 否 | `interpolated`（默认，等间隔取值）/ `avg` / `max` / `min`（按间隔窗口统计）/ `raw`（原始存储值） |
| `limit` | 否 | 每点最多样本数，默认且上限 10000（`MOCK_DCS_MAX_POINTS`） |

为减少将来对齐时的改动，也接受这些别名：`beginTime`/`start`、`end`、`step`/`period`、`mode`/`type`、`maxCount`、`nodeIdList`/`ids`。

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "nodeId": "10:PT_1003.PV",
      "count": 61,
      "values": [
        { "t": 1790086907000, "q": 1, "v": 0.455 },
        { "t": 1790086967000, "q": 1, "v": 0.476 }
      ]
    }
  ]
}
```

`raw` 模式说明：开关量只返回区间起点的值 + 此后每次变位（天然就是"泵什么时候启停"的答案）；
模拟量按 5 s 存储步长返回。超出 `limit` 时该点多一个 `"hasMore": true`。

## 四、错误码

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000 | 请求体不是 JSON 对象 |
| 40001 | 参数错误（缺 nodeIds / startTime、格式无法识别、sampleMode 非法、interval < 1000 等） |
| 40002 | 单次点数超过上限 |
| 40003 | startTime 不早于 endTime |
| 40004 | 每点预计样本数超过上限（提示加大 interval 或缩短时间范围） |

错误时 `data` 为 `null`，`message` 为可读原因。

## 五、数值是怎么"制造"的

### 5.1 按测点画像给范围

先看单位，再看现场描述关键词，最后看位号前缀（TI/PT/LT/FT/AT……）。节选：

| 测点特征 | 类别 | 合理范围 |
| --- | --- | --- |
| ℃ + 水解 | 酶法水解温度 | 34 ~ 38 ℃ |
| ℃ + 结晶 | 低温结晶 | 2 ~ 12 ℃ |
| ℃ + 冷盐水/冷冻 | 冷媒 | −12 ~ −2 ℃ |
| ℃ + 蒸汽/蒸发/精馏/塔釜 | 高温段 | 85 ~ 118 ℃ |
| pH + 水解 | 水解 pH | 7.7 ~ 8.1 |
| pH + 结晶 | 6-APA 等电点结晶 | 3.9 ~ 4.4 |
| pH + 萃取/酸 | 酸化萃取 | 1.8 ~ 2.6 |
| MPa + 泵后/出口 | 泵出口压力 | 0.25 ~ 0.55 MPa |
| MPa + 真空 | 真空度 | −0.095 ~ −0.080 MPa |
| kPa + 蒸发/真空 | 绝压 | 4 ~ 15 kPa |
| % + 阀 + 反馈 | 阀位反馈 | 20 ~ 80 %，跟随给定 |
| A（电流）/ Hz / rpm | 电机 | 运行时在范围内，**停机为 0** |
| kg/m³ + 丁酯/有机相 | 有机相密度 | 860 ~ 890 |
| 备用点（描述"备用"、位号 BY/SPA 开头） | 未接线 | 模拟量 q=0；开关量 0 |

完整规则见 `mock_dcs/profiles.py`；某个点命中了哪条规则：`GET /api/mock/profile?nodeId=…`

### 5.2 让相关测点互相对得上

同一设备 / 阀门的测点共享同一个状态（按位号去掉 `_RUN/_DO/_OF/_CF/_IB/_FB/_AO…` 尾缀后归并）：

- 开反馈（`_OF`）与关反馈（`_CF`）**恒互补**
- 运行反馈、启停指令、电流、频率**同起同停**，停机时电流/频率归零
- 阀位反馈（`_FB`）跟随同一阀门的开度给定（`_AO`），滞后 30 s
- 启动/停止脉冲指令（`_QD/_TZ`）常为 0；故障常为 0；远程/就地常为 1（远程）

### 5.3 实时与历史出自同一条曲线

每个点的值是 **(种子, 测点, 时间) 的纯函数**：

```
模拟量 = 基线 + 慢周期波动(20 min ~ 3 h) + 快周期波动(2 ~ 12 min) + 1 s 扫描噪声，夹到合理范围
开关量 = 按 15 ~ 90 min 时间片切换的设备状态，运行占比 80%（阀门 60%）
```

所以：同一时刻查实时值和查历史值拿到的是同一个数；同一段历史查两次完全一样；服务重启不改变"已经发生过"的历史。
换 `MOCK_DCS_SEED` 相当于换一套工况。

## 六、自测结果

`MOCK_DCS_URL=http://localhost:8900 python3 -m tests.test_mock_dcs` → **34 / 34 通过**

- 响应格式与接口示例逐字段一致（顶层 code/message/data，逐项 nodeId/st/t/q/v）
- 全点表 10,680 个点：模拟量越界 0，开关量只取 0/1，非备用点质量全部为 1，503 个备用模拟量返回 q=0
- 开/关反馈互补 766/766 组；阀位反馈跟随给定 267/267 组；运行状态与电流/频率一致 116/116 组
- 历史：等间隔、可复现、实时与历史一致、raw 只返回变位点、min ≤ avg ≤ max、未来时间截断、自动步长
- 9 种异常参数均返回对应错误码

## 八、配置

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `MOCK_DCS_PORT` / `MOCK_DCS_HOST` | 监听 | `8900` / `0.0.0.0` |
| `MOCK_DCS_ONTOLOGY_URL` | 点表来源（不填则用 `ONTOLOGY_BASE_URL`） | `http://localhost:8700` |
| `MOCK_DCS_STRICT_NODES` | 点表里没有的点是否返回坏质量 | `false` |
| `MOCK_DCS_SEED` | 数据种子 | `6apa` |
| `MOCK_DCS_MAX_NODES` / `MOCK_DCS_MAX_POINTS` | 单次点数 / 每点样本数上限 | `500` / `10000` |
| `MOCK_DCS_TZ_OFFSET` | 时间字符串时区（小时） | `8` |
