# 一、背景与场景

## 1.1 背景

105 车间是 6-APA 原料药合成车间，主工艺由八道工序组成：**提取、水洗、脱色、抽取、水解、萃取、薄膜、结晶**。RB 液是水解反应最主要的原料，来自上游 104 车间发酵。

工艺出现异常后（收率下降、温度 / pH 长时间偏离等），工艺员需要：

1. 翻阅人工维护的工艺台账，判断异常大致落在哪几天、哪个罐、哪个批次；
2. 在 XBase 中逐个测点查看趋势，手动导出数据画图、算最大 / 最小 / 平均；
3. 取 LIMS 或人工化验数据，佐证在线数据是否准确；
4. 凭个人经验判断原因，调整温度、pH、氨水进量等操作参数，再次取样验证；
5. 回忆或翻查历史上是否出现过同类情况。

调研反映的核心问题：

- **切入点多、方法不统一**：异常后可能的切入点很多（pH 靠近上下限、氨水进不去、甲氨量不够……），每位工艺员的排查方式不同；现场**没有出现概率较大的典型异常**，难以套用固定优先级。
- **数据分散、时段不准**：调查时间应以每个水解罐的反应起止时间为准，而不是固定时长；化验数据与 DCS 存在时间差，且无法直接对应到具体反应罐。
- **因素未覆盖**：人为修改控制参数、班次、季节、酶活性衰减、上游来料等因素没有纳入分析。
- **结果无沉淀**：分析记录不存档，历史案例无法检索，排查模板为员工自行整理。
- **限值静态**：工艺参数上下限实际是动态的，随工况、酶活、批次数调整。

## 1.3 用户角色

| 角色 | 业务职责 | 使用时机 | 主要诉求 |
|---|---|---|---|
| 工艺员（工艺调查员） | 工艺异常调查全流程：定位阶段、佐证、排查、调整、验证 | 收率异常；操作员反馈温度 / pH 长时间有问题 | 统一排查切入点；替代手动导数画图；化验与在线比对；历史同类检索；报告模板 |
| 操作员 | 监控温度、pH，反馈异常 | 发现参数长时间偏离时 | 分析记录可查；按标准流程逐项排查 |
| 车间主任 | 关注调查效率与依据 | 审阅调查结论 | 结论有数据依据；原因可设权重；易用、易维护；化验 / 操作数据只录一遍 |
| 化验员 | 化验取样与录入 | 批次化验 | 化验结果只录一遍，自动对应到罐与时段 |
| 信息化部 | 系统建设与合规 | 系统上线与验证 | 数据不出车间；可追溯；满足 GMP / CSV 要求 |

## 1.4 现场业务事实（调研沉淀）

以下为调研中由用户明确给出、可直接作为需求或知识输入的业务事实：

|---|---|---|

| BF-06 | 操作员最关注温度和 pH；上游工艺能否进入水解只看 pH；酶活性影响上下限的设置 | 10.16 操作员 |
| BF-07 | 现场经验基准：批次越多，pH / 温度设置越高；批次高且残留高往往伴随温度高；批次新且温度低需要开展工艺调查 | 10.19 力兴业 |

| BF-13 | 化验数据与 DCS 操作存在时间差且无法完整对齐；化验数据目前无法直接对应到具体反应罐 | 10.21 王金东 |
| BF-14 | 排班使用 MOM 的 worktrans 模块；班次可用于精确到班次的异常调查，结合操作记录定位人为原因 | 10.22 王金东 |
| BF-15 | DCS 组态图更接近现场实际工艺，可转化为工艺图谱，但缺少仪表、阀门信息，结晶罐位置与实际不一致 | 10.22 王金东 |
| BF-16 | Cpk、6σ 等统计方法在年度数据回顾时使用 | 10.21 王金东 |
| BF-17 | 工艺调查模板可接受手工画图、Excel 输入的填写方式；现有模板（异常工艺排查记录、调查报告、改正措施保证书）为员工自行整理 | 10.16 力兴业；10.21 王金东 |

# 三、需求分解原则

## 3.1 职责划分

借鉴 XWorld 本体、知识图谱、知识库的定位，结合 Demo 现有架构，四类承载方的职责如下：

| 承载方 | 负责什么 | 不负责什么 | Demo 中的对应 |
|---|---|---|---|
| **本体**（本体服务） | 对象是什么、对象之间什么关系、属性绑定什么数据、什么条件下生效什么约束、对象能挂什么能力、经确认的事件与案例结构 | 计算、判断执行、对话、报告、留痕、文档原文 | 本体服务 8700：Excel 数据源 + 加载器 + REST 接口 + 资产本体页 |
| **知识库** | 规程、SOP、模板、历史报告、偏差档案等文档原文及切片，可检索、可引用 | 结构化约束与关系（经确认后进入本体） | 尚无；`docs/SOP-S11-ALARM-001.md` 为文档雏形 |
| **Agent**（编排与固定程序） | 理解问题、编排调查流程、调用固定程序做确定性计算、调用外部数据、组织证据、生成报告素材、调查记录与存档、**全程留痕审计**、权限与边界控制 | 定义对象和约束（读本体）；存文档原文（读知识库） | Agent 8800：大模型 + 43 个工具（33 个本体接口、10 个固定程序）+ 运行时 |
| **外部系统** | 数据本身：过程数据、批次与操作记录、化验、排班 | 语义与分析 | XBase（Demo 以模拟 DCS 8900 代替）、EBR、MOM、LIMS |

几条划分原则：

1. **定义在本体，执行在 Agent。** 例如"pH 在线与化验差值恒定或变大判异常"：判定规则的定义（对象、参数、阈值、适用阶段）登记在本体；按规则取数比对是 Agent 的固定程序。
2. **原文在知识库，结构在本体。** 规程原文入知识库；从规程中整理出的处置卡（原因、检查项、步骤）经确认后进入本体。Demo 中 S11 规程与 10 张处置卡即为此模式。
3. **事实在外部系统，语义在本体。** 本体不存实时值、化验值，只存"这个属性由哪个位号 / 化验项目 / 录入字段提供"。
4. **留痕、存档、报告、权限属于 Agent。** 本体只记录自身的变更历史（版本）。
5. **未确认的不参与确定性判断。** 本体中的候选关系、推断限值保留"待确认"状态；Agent 使用时必须标明，不作为确定依据。

# 九、待确认问题

1. EBR 上线排期与接口方式；EBR 未就绪期间，以 DCS 信号推断反应时段是否可接受，推断依据由谁确认。
2. 化验数据如何对应到具体水解罐；化验与 DCS 的时间对齐规则（取样时间、出结果时间、反应阶段）。
3. DCS 操作日志 / 审计追踪是否可获取，粒度是否包含操作人、操作站、前后值。
4. 动态限值的"差值"取多少、依据是什么；批次段（如 100 批以内、100～1000 批）对应的限值与残留标准。
5. pH 在线—化验差值"恒定或变大"的判定阈值与观察窗口。
6. 原因权重由谁维护、如何更新；是否随案例积累自动调整。
7. 统一排查模板的字段与审批要求，是否需要与 QMS 对接。
8. 季节 / 环境因素的数据来源（环境温度、湿度）。
9. 八道工序与 DCS 工段的对应口径（Demo 现以 24 个工段组织）。
10. 本地 GPU 资源与模型选型；推理时延目标在目标硬件上的验证。
11. 试点阶段的留痕要求是否需要满足 CSV 的审计追踪规范（如不可删除、电子签名）。
12. 本体、处置卡、案例的日常维护由工艺员、实施人员还是 AI 辅助完成。

# 十、总体原则

1. **复刻工艺员的路径，而不是替代判断。** 以 BF-03 的排查路径为主线，AI 负责找数据、算证据、给方向，结论由工艺员确认。
2. **水解先行，按模式复制。** 水解工序的设备归并、实例连接、处置卡、阶段与上下文模式跑通后，按同一模式扩展其余七道工序。
3. **定义在本体，执行在 Agent，原文在知识库，数据在外部系统。**
4. **固定程序优先，大模型解释。** 确定性计算可复现、可审计；大模型负责理解、编排与表述。
5. **未确认不作为依据。** 推断的限值、关系、案例都带状态，使用时标明。
6. **只读、本地、可追溯。** 不写生产系统，不出车间，全程留痕。
